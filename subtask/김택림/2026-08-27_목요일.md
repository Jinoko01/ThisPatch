# TIL - 2026-08-27 (목)

## 오늘 한 것

오늘은 Steam에서 실제로 활용할 수 있는 데이터를 다시 정리하고, 패치 분석에만 한정하지 않고 어떤 기능으로 확장할 수 있을지 아이디어를 검토했다.

Steam 데이터로 만들 수 있는 기능 중 활용 가능성이 있어 보이는 4가지 아이디어를 중심으로 정리해보았다.

---

## 1. 유사 장르 게임 Benchmark

비슷한 장르와 Tag를 가진 Steam 게임들의 정보를 모아 게임 기획 단계에서 참고할 수 있는 Benchmark를 제공하는 기능을 정리했다.

주요 지표는 다음과 같다.

- 가격 중앙값
- 리뷰 작성자 플레이타임 중앙값
- DLC 보유 비율
- Workshop 지원 비율
- 해당 장르에서 자주 나타나는 주요 불만 VOC

예를 들어 `FPS + Tactical`과 비슷한 게임들을 모아 실제 시장에서 어떤 가격과 플레이타임 분포를 가지는지 확인할 수 있다.

중요한 점은 적정 가격이나 운영 전략을 직접 추천하는 것이 아니라, 비슷한 게임들의 실제 데이터를 참고할 수 있도록 제공하는 것이다.

---

## 2. 플레이타임 구간별 Review VOC

Steam Review의 `playtime_at_review`를 활용해 비슷한 장르의 리뷰를 플레이타임 구간별로 분석하는 기능을 정리했다.

예:

```text
0~10h
10~100h
100~500h
500h+
```

각 구간에서 어떤 Positive / Negative Topic이 많이 등장하는지 비교한다.

예를 들어 초기 플레이타임 리뷰에서는 Tutorial, UI, Difficulty 관련 내용이 많고, 장시간 플레이 리뷰에서는 Balance, Meta, Cheating 관련 내용이 많을 수 있다.

이를 통해 플레이타임이 다른 리뷰 작성자 집단에서 어떤 문제를 주로 언급하는지 확인할 수 있다.

---

## 3. 초기 플레이타임 + 환불 Review 분석

Review API POC에서 `playtime_at_review`와 `refunded` 필드를 확인했기 때문에 이를 함께 활용하는 아이디어를 구체화했다.

분석 대상은 다음과 같다.

- 낮은 플레이타임의 Negative Review
- Refunded Review
- 낮은 플레이타임 + Refunded Review

예:

```text
0~2h Negative Review

Crash
Performance
Control
Tutorial
Difficulty
```

또는

```text
Refunded Review

Performance
Crash
Compatibility
Control
```

처럼 주요 Topic을 추출한다.

이를 통해 초기 플레이타임 또는 환불 리뷰에서 반복적으로 언급되는 문제를 확인할 수 있다.

다만 특정 Topic을 실제 이탈이나 환불의 직접적인 원인이라고 단정하지 않고, 해당 리뷰 집단에서 자주 관측되는 문제로 표현하기로 했다.

---

## 4. 유사 패치 기반 QA Intelligence

현재 개발 중인 패치와 비슷한 Steam의 과거 패치를 검색하고, 당시 사용자 리뷰에서 어떤 문제가 많이 등장했는지 보여주는 기능을 정리했다.

예를 들어 현재 패치에 다음 변경이 있다고 가정한다.

```text
Smoke Rendering 변경
```

패치 내용을 구조화한 뒤 과거 유사 변경을 검색한다.

```text
현재 패치
Smoke Rendering 변경
        ↓
과거 유사 패치 검색
        ↓
유사 사례 42건
```

그리고 해당 패치 이후 반복적으로 등장했던 VOC를 집계한다.

```text
FPS Drop       15건
Visibility     12건
Stuttering      9건
```

이 결과를 기반으로 QA에서 참고할 수 있는 항목을 제공한다.

예:

```text
- 다수 Smoke 렌더링 상황 성능 확인
- Smoke Visibility 확인
- 저사양 환경 Stuttering 확인
```

핵심은 패치의 성공이나 실패를 예측하는 것이 아니라, 과거 유사 변경 이후 실제 사용자들이 어떤 문제를 언급했는지 참고할 수 있도록 하는 것이다.

## 기능 흐름 정리

오늘 검토한 기능들을 흐름으로 연결하면 다음과 같이 볼 수 있었다.

```text
게임 기획 단계
    │
    ├─ 유사 장르 Benchmark
    ├─ 플레이타임별 Review VOC
    └─ 초기/환불 Review VOC
    │
    ↓
개발 / QA 단계
    │
    └─ 현재 패치
          ↓
       과거 유사 패치 검색
          ↓
       당시 사용자 불만 분석
          ↓
       QA 참고자료
```

Localization, Achievement, DLC 운영, Workshop 분석 등 다른 아이디어도 함께 살펴봤지만, 이번에는 위 4가지 기능의 활용 가능성을 중심으로 정리했다.

## 배운 것

Steam Review 데이터의 필드를 단순히 저장하는 것보다, 여러 필드를 조합했을 때 더 의미 있는 기능을 만들 수 있다는 점을 알게 되었다.

예를 들어 다음 데이터만으로도 여러 분석이 가능하다.

```text
Review Text
+
Playtime at Review
+
Refunded
+
Game Tag
```

이를 활용하면 플레이타임별 VOC, 초기 플레이타임 분석, 환불 리뷰 분석 등으로 확장할 수 있다.

또한 Patch Note와 Review 데이터를 연결하면 단순 리뷰 분석을 넘어 과거 유사 패치 사례를 QA 참고자료로 활용할 수 있다.
