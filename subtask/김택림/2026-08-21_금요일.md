# TIL - 2026-08-21 (금)

## 오늘 한 것

`AllPairPartition`, `AllPairPartitionSelf`, `CommonItemCount`를 구현하며 전체 조합 파티셔닝과 다단계 MapReduce 처리를 학습했다.

### 1. `AllPairPartition`

- 각 tuple을 임의의 파티션에 배정했다.
- 두 테이블의 tuple을 `(partitionId, i)`와 `(i, partitionId)` 형태의 key로 여러 파티션 조합에 배치했다.
- Reducer에서 같은 파티션 조합의 tuple을 묶어 후속 pair 비교를 위한 블록을 만들었다.

### 2. `AllPairPartitionSelf`

- 하나의 테이블에서 전체 조합을 만들기 위한 파티션 배치를 작성했다.
- `min(partitionId, i)`, `max(partitionId, i)`로 key 순서를 정규화했다.
- 같은 파티션 조합이 중복으로 처리되지 않도록 구성했다.

### 3. `CommonItemCount`

- 1단계에서 `item → record id` 형태의 역색인을 만들었다.
- 같은 item을 공유하는 record id 쌍을 생성하고 각 쌍에 `1`을 부여했다.
- 2단계에서 record id 쌍의 순서를 정규화한 뒤 값을 합산해 공통 item 개수를 계산했다.

## 배운 것

- 전체 조합 문제에서는 파티션 조합을 key로 설계해 비교 대상 데이터를 같은 Reducer로 보낼 수 있다.
- `min`, `max`를 활용해 쌍의 순서를 통일하면 중복 계산을 줄일 수 있다.
- 하나의 문제를 여러 MapReduce Job으로 나누고 앞 단계의 결과를 다음 단계의 입력으로 사용할 수 있다.

## 느낀 점

이번 주에는 단순한 WordCount부터 시작해 데이터 분배, 역색인, 행렬 연산, 조합 처리까지 다양한 MapReduce 패턴을 경험했다. 문제의 핵심은 Mapper와 Reducer의 코드보다 어떤 key를 만들고 데이터를 어떻게 묶을지 결정하는 데 있다는 것을 알게 되었다.
