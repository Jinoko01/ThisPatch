## 1. TypeScript의 등장 배경과 기본 문법 체계

- **TypeScript 등장 배경**:
  - JavaScript는 동적 타입 언어로 런타임에 타입 에러가 발견되어 대규모 프로젝트에서 유지보수와 안정성에 취약하다.
  - TypeScript는 JavaScript의 상위 집합(Superset)으로, 정적 타입을 도입하여 **컴파일(빌드) 타임에 오류를 사전에 검출**하고 IDE 자동완성과 생산성을 극대화한다.
- **핵심 기본 문법**:
  - **기본 타입**: `string`, `number`, `boolean`, `null`, `undefined`, 배열(`number[]` 또는 `Array<number>`), 튜플 등
  - **인터페이스 & 타입 별칭**:
    - `interface User { id: number; name: string; email?: string; }`
    - `type Status = 'idle' | 'loading' | 'success' | 'error';` (유니온 타입 활용)
  - **함수 타입 지정**: 매개변수와 반환값의 타입을 명시하여 예기치 않은 인자 전달 방지

## 2. React Virtual DOM의 동작 원리와 렌더링 성능 최적화

- **기존 Real DOM 조작의 문제점**:
  - DOM 변경이 발생하면 브라우저는 레이아웃 계산(**Reflow**)과 픽셀 그리기(**Repaint**) 과정을 거치며, 잦은 직접 DOM 수정은 심각한 성능 저하를 유발한다.
- **Virtual DOM(가상 돔)이란?**:
  - 실제 브라우저 DOM을 가벼운 JavaScript 객체 형태로 메모리에 표현한 추상화 계층이다.
- **Virtual DOM이 빠른 이유 (동작 메커니즘)**:
  1. **상태 변경 감지**: 컴포넌트의 `state`나 `props`가 변경되면 새로운 Virtual DOM 트리를 메모리에 생성한다.
  2. **Diffing (비교 알고리즘)**: 이전 Virtual DOM 트리와 새 가상 트리를 $O(n)$ 휴리스틱 알고리즘으로 효율적으로 비교하여 변경된 노드만 찾아낸다.
  3. **Reconciliation (재조정) & Batching (일괄 처리)**: 변경된 부분들만 모아서 한 번의 연산으로 실제 DOM에 일괄(Batch) 패치함으로써 브라우저의 Reflow/Repaint 발생 횟수를 최소화한다.

## 3. JSX 문법과 브라우저 요소 렌더링 메커니즘

- **JSX (JavaScript XML)의 본질**:
  - JSX는 HTML처럼 보이지만 브라우저가 직접 이해할 수 없는 자바스크립트 확장 문법이다.
  - 빌드 타임에 Babel과 같은 트랜스파일러에 의해 `React.createElement(type, props, ...children)` 함수 호출로 변환된다.
  - 변환 결과물은 일반 JavaScript 객체(React Element)이며, 이것이 모여 Virtual DOM 트리를 형성한다.
- **JSX 문법 필수 규칙**:
  - **단일 루트 요소**: 컴포넌트는 반드시 하나의 부모 태그(또는 Fragment `<> ... </>`)로 감싸야 한다.
  - **자바스크립트 표현식 삽입**: 중괄호 `{}` 내에 변수, 연산, 함수 호출 등의 JS 식을 작성할 수 있다.
  - **카멜 표기법(camelCase)**: HTML 속성명 대신 `className`, `htmlFor`, `onClick` 등을 사용한다.

## 4. React 컴포넌트 제어문 (조건부 및 리스트 렌더링)

- **조건부 렌더링 (Conditional Rendering)**:
  - **삼항 연산자 (`condition ? <A /> : <B />`)**: 조건에 따라 서로 다른 컴포넌트나 요소를 분기하여 렌더링할 때 사용
  - **논리 AND 연산자 (`condition && <A />`)**: 조건이 참일 때만 특정 요소를 출력하고, 거짓일 때는 아무것도 그리지 않을 때 활용
  - **Early Return**: 컴포넌트 상단에서 특정 조건(예: 로딩, 에러) 만족 시 즉시 다른 JSX를 반환
- **리스트 렌더링과 `key` prop (반복 제어)**:
  - JavaScript 배열의 `map()` 함수를 활용하여 데이터 배열을 JSX 요소 배열로 변환해 출력
  - **`key` prop의 중요성**:
    - React가 Virtual DOM Diffing 시 어떤 항목이 추가, 수정, 삭제되었는지 식별하는 고유 식별자 역할을 한다.
    - 배열의 단순 `index` 대신 고유한 ID(예: `item.id`)를 `key`로 지정해야 불필요한 리렌더링 및 상태 꼬임 버그를 방지할 수 있다.
