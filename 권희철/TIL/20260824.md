# TIL 2026-08-24 (월)

## 1. 빅데이터 분산 처리의 개념 및 필요성

- **단일 머신(Scale-up)의 한계**: 데이터 양이 테라바이트(TB) 이상으로 증가함에 따라 단일 서버의 CPU, 메모리, 디스크 확장만으로는 비용과 물리적 한계에 부딪힌다.
- **분산 시스템(Scale-out)의 등장**: 여러 대의 상용 서버(노드)를 네트워크로 연결하여 하나의 클러스터로 구성하고, 데이터를 분할하여 병렬로 저장 및 처리하는 방식이다.
- **주요 특징**:
  - **데이터 파티셔닝**: 대규모 데이터를 여러 노드에 나누어 분산 저장/처리한다.
  - **내결함성(Fault Tolerance)**: 특정 노드에 장애가 발생해도 데이터 복제본과 재시도 메커니즘을 통해 시스템이 안정적으로 유지된다.
  - **병렬 컴퓨팅**: 여러 작업자가 동시에 분할된 작업을 수행하여 전체 처리 속도를 대폭 향상시킨다.

## 2. 빅데이터 도메인 기술 스택 및 파이프라인 개요

- 빅데이터 도메인에서 프로젝트 주제를 구상하기 위해 데이터 라이프사이클에 따른 기술 스택 계층을 정리했다.
  - **수집(Ingestion)**: 로그, 이벤트, 외부 API 등에서 실시간/배치 데이터를 수집 (Kafka, Flume, Logstash 등)
  - **저장(Storage)**: 대규모 정형/비정형 데이터를 안전하게 보관 (HDFS, S3, NoSQL 등)
  - **처리/분석(Processing)**: 분산 클러스터를 활용한 대규모 데이터 가공 및 연산 (Hadoop MapReduce, Spark, Flink 등)
  - **서빙 및 쿼리(Serving/DB)**: 가공된 데이터를 빠른 조회가 가능하도록 인덱싱 및 저장 (ClickHouse, Elasticsearch, PostgreSQL 등)
  - **시각화(Visualization)**: 프론트엔드 대시보드를 통한 실시간 차트 및 지표 표출

## 3. 핵심 분산 기술 스택 비교 분석

빅데이터 처리 파이프라인의 핵심 기술들을 비교하고 각각의 강점과 용도를 파악했다.

- **Apache Kafka**:
  - **역할**: 고성능 분산 이벤트 스트리밍 플랫폼 (메시지 브로커)
  - **특징**: 높은 처리량(Throughput)과 영속성을 가지며, 발행/구독(Pub/Sub) 모델을 통해 대규모 실시간 로그 수집의 완충재 역할을 한다.
- **Apache Hadoop**:
  - **역할**: 대용량 데이터 분산 저장 및 배치 처리 프레임워크
  - **특징**: HDFS(Hadoop Distributed File System)를 통한 파일 분산 저장과 MapReduce를 통한 대용량 배치 연산의 기반을 제공한다.
- **Apache Spark**:
  - **역할**: 인메모리(In-Memory) 기반의 고속 분산 데이터 처리 엔진
  - **특징**: 디스크 I/O를 최소화하여 Hadoop 대비 최대 100배 빠른 연산 속도를 지원하며, 배치 처리와 마이크로 배치 기반 스트리밍(Spark Streaming), SQL, 머신러닝 라이브러리를 통합 제공한다.
- **Apache Flink**:
  - **역할**: 저지연(Low-latency) 실시간 스트림 처리 엔진
  - **특징**: 마이크로 배치가 아닌 진정한 이벤트 단위(Event-driven) 스트리밍 처리를 지원하며, 실시간 윈도우 연산과 상태 관리(State Management)에 매우 강력하다.

## 4. 프론트엔드 관점에서의 빅데이터 연동 및 시각화 준비

- **FE의 역할 정의**: 프론트엔드는 Hadoop/Spark를 직접 제어하기보다, 분산 클러스터가 집계하여 서빙 계층(API)으로 내려준 대용량 데이터를 빠르고 매끄럽게 사용자에게 보여주는 UI/UX를 설계하는 것이 핵심이다.
- **대용량 데이터 렌더링 최적화**:
  - 수천~수만 건의 리스트를 한 번에 DOM에 그리지 않고, **가상 스크롤(Virtual Scrolling)** 및 페이지네이션을 적용하는 기법을 검토했다.
- **데이터 통신 방식**:
  - 정기적 통계 조회는 REST API/GraphQL을 사용하고, 실시간 스트리밍 지표는 **웹소켓(WebSocket)** 또는 SSE(Server-Sent Events)를 연동하는 흐름을 비교했다.
- **대시보드 차트 시각화**:
  - 집계된 시계열 데이터 및 분포도를 효과적으로 표현하기 위한 차트 라이브러리(ECharts, Chart.js 등)의 렌더링 성능과 프론트 최적화 방안을 정리했다.
