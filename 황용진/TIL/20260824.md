# Hadoop, Spark, Kafka의 역할 이해하기

세 기술 모두 빅데이터를 다룬다고 해서 처음에는 역할이 비슷할 것이라고 생각했다. 하지만 사용자 행동 데이터를 수집하고 분석하는 흐름에 대입해 보니, 데이터를 저장하고 전달하고 계산하는 역할을 나누어 이해하는 것이 편했다.

| 기술 | 중심 역할 | 사용 예시 |
| --- | --- | --- |
| Hadoop HDFS | 대용량 파일을 여러 서버에 분산 저장 | 원본 로그와 분석 데이터 보관 |
| Spark | 대규모 데이터를 분산 처리하고 집계 | 상품별 클릭 수, 시간대별 이용량 계산 |
| Kafka | 이벤트를 저장하고 여러 시스템이 읽도록 제공 | 사용자 행동 수집, 서비스 간 비동기 전달 |

Hadoop 전체가 저장소만을 의미하는 것은 아니다. 우선 HDFS를 저장, Spark를 처리, Kafka를 이벤트 전달의 관점에서 구분하고 각 기술이 어디에 쓰이는지 알아보기로 했다.

---

# Hadoop: 데이터를 여러 서버에 나누어 저장하고 처리하기

Hadoop은 여러 컴퓨터를 이용해 대규모 데이터를 저장하고 처리하기 위한 프레임워크이다. 구성 요소별로 역할이 나뉜다.

- **HDFS**: 파일을 블록으로 나누어 여러 서버에 저장하는 분산 파일 시스템이다.
- **YARN**: 클러스터의 CPU와 메모리 등 작업에 필요한 자원을 관리한다.
- **MapReduce**: 데이터를 나누어 처리하고 결과를 모으는 분산 처리 방식이다.

Spark와 함께 사용한다면 HDFS가 저장을, Spark가 계산을 담당하고 YARN이 실행 자원을 관리하는 구성을 생각할 수 있다.

## HDFS는 어떻게 사용하는가

HDFS에서는 NameNode가 파일 경로와 블록 위치 등의 메타데이터를 관리하고, DataNode가 실제 데이터 블록을 저장한다. 블록을 여러 노드에 복제해 일부 노드의 장애에 대비할 수 있으며, 복제에 사용하는 만큼 실제 저장 공간도 필요하다.

```text
NameNode → 파일과 블록 위치 관리
DataNode → 실제 블록 저장
```

HDFS 접속 설정과 실행 환경이 준비되어 있다면 다음처럼 로컬 파일을 올리고 확인할 수 있다.

```bash
hdfs dfs -mkdir -p /data/events
hdfs dfs -put events.json /data/events/
hdfs dfs -ls /data/events
hdfs dfs -cat /data/events/events.json
```

사용자 정보 한 건을 자주 수정하는 서비스 DB보다는, 많은 로그와 분석용 파일을 쌓아두고 대량으로 읽는 상황에 어울린다고 이해했다. 먼저 파일을 넣고 읽는 흐름부터 익히면 Spark가 어떤 데이터를 가져가 처리하는지도 연결해서 볼 수 있을 것 같다.

# Spark: 쌓인 데이터를 계산 가능한 결과로 만들기

Spark는 대규모 데이터를 여러 컴퓨터에서 병렬로 처리할 수 있는 엔진이다. 예를 들어 사용자 클릭 로그가 많이 쌓였을 때, 상품별 클릭 수를 계산하거나 특정 조건의 이벤트만 추출하는 데 사용할 수 있다.

- **Driver**: 전체 작업의 실행을 계획하고 조정한다.
- **Executor**: 할당된 작업을 실행하고 데이터를 처리하는 프로세스이다.
- **DataFrame**: 행과 열로 구성된 데이터를 다루는 API이다.

## DataFrame으로 집계하기

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.master("local[*]").appName("ClickCount").getOrCreate()
events = spark.createDataFrame(
    [(100, "CLICK"), (100, "CLICK"), (200, "VIEW")],
    ["productId", "event"],
)
result = events.filter(events.event == "CLICK").groupBy("productId").count()
result.show()
spark.stop()
```

클릭 이벤트만 남기고 상품별로 묶어 개수를 계산하는 예시이며, 상품 100의 클릭 수는 2가 된다. 여기서는 로컬에서 실행하지만, 큰 데이터는 클러스터에서 나누어 처리할 수 있다.

`filter()` 같은 변환은 실행 계획을 만들고, `show()` 같은 Action이 호출되면 계산을 수행한다. 이를 Lazy Evaluation이라고 한다. 위의 `groupBy(...).count()`는 집계 결과를 표현하는 DataFrame을 만들며, 전체 행 수를 바로 구하는 `df.count()`와 구분해야 한다.

HDFS의 파일을 읽어 일괄 처리할 수도 있고, Structured Streaming으로 Kafka에서 계속 들어오는 이벤트를 처리할 수도 있다. Spark는 처리 엔진이므로 Hadoop이 반드시 있어야 실행되는 것은 아니라는 점도 함께 정리했다.

# Kafka: 이벤트를 여러 시스템으로 연결하기

Kafka는 이벤트를 저장하고 소비할 수 있게 하는 분산 이벤트 스트리밍 플랫폼이다. 사용자 클릭이 발생할 때 백엔드가 통계, 추천, 로그 시스템을 모두 직접 호출하면 각 시스템의 상태에 영향을 받기 쉽다. Kafka에 이벤트를 기록하고 필요한 시스템이 따로 읽도록 하면 이러한 연결을 줄일 수 있다.

| 용어 | 역할 |
| --- | --- |
| Producer | Kafka에 이벤트를 보내는 프로그램 |
| Consumer | Kafka에서 이벤트를 읽는 프로그램 |
| Topic | 이벤트를 종류별로 구분하는 논리적 단위 |
| Broker | 이벤트를 저장하고 읽기·쓰기를 처리하는 Kafka 서버 |
| Partition | Topic을 나눈 단위로, 분산 저장과 병렬 소비에 사용 |
| Offset | Partition 안에서 이벤트의 위치를 나타내는 값 |
| Consumer Group | 여러 Consumer가 Partition을 나누어 처리하는 그룹 |

## 사용자 행동 이벤트에 적용하기

```text
Backend(Producer) → Kafka의 user-events Topic
                         ├→ 통계 Consumer Group
                         └→ 추천 Consumer Group
```

서로 다른 Consumer Group은 같은 이벤트를 각자의 목적으로 읽을 수 있다. 한 그룹 안에서는 Partition을 나누어 처리하고, 순서는 Topic 전체가 아닌 Partition 내부를 기준으로 이해해야 한다.

또한 Consumer가 읽었다고 이벤트가 즉시 삭제되는 것은 아니다. 보관 정책 안에서 이벤트를 유지하므로 소비 위치를 관리하며 다시 읽을 수 있다. 처리하는 쪽이 잠시 느려져도 이벤트를 보관하며 속도 차이를 흡수할 수 있지만, 보관 기간과 용량을 넘기지 않도록 관리해야 한다.

Kafka 자체에서 상품별 클릭 수가 자동으로 계산되는 것은 아니다. 이벤트를 전달받은 Spark나 별도의 Consumer가 필요한 처리를 수행한다고 이해했다.

# 세 기술을 함께 사용한다면

사용자 행동 분석을 예시로 두면 역할이 더 명확해진다.

```text
사용자 클릭 → Backend → Kafka → Spark → HDFS
                        이벤트   집계     결과 파일
```

1. Backend가 사용자 클릭을 이벤트로 만들어 Kafka에 보낸다.
2. Spark가 Kafka의 이벤트를 읽어 상품별 클릭 수 등을 집계한다.
3. 처리 결과를 HDFS에 저장해 이후 분석에 활용한다.

반대로 HDFS에 쌓인 원본 로그를 Spark로 읽어 하루 단위로 집계하는 배치 처리도 가능하다. Kafka와 Spark의 연동에는 버전에 맞는 커넥터가 필요하고, 스트리밍 결과 저장은 집계 방식과 저장 대상에 맞게 구성해야 한다. 위 흐름은 각 역할을 이해하기 위한 구성 예시이다.

세 기술을 무조건 함께 도입해야 하는 것은 아니다. 데이터 규모, 실시간 처리 필요성, 운영 부담을 먼저 보고 필요한 구성을 선택해야 한다고 생각했다.

# 정리와 다음 학습

이번에는 세부 설정을 외우기보다 HDFS는 파일을 보관하고, Kafka는 이벤트를 연결하며, Spark는 데이터를 계산한다는 관계를 이해하는 데 집중했다.

- HDFS: 파일 하나를 올리고 다시 읽어보기
- Spark: 작은 DataFrame에서 필터링과 집계 수행하기
- Kafka: Producer가 보낸 이벤트를 Consumer에서 확인하기
- 이후 HDFS의 파일 읽기와 Kafka 스트림 처리를 Spark에 연결해 보기

각각의 작은 사용 흐름부터 익힌 뒤, 사용자 행동 데이터가 수집되어 분석 결과로 남는 과정까지 연결해 볼 계획이다.
