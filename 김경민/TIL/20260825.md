## 사전학습 — MapReduce 기본 응용

### WordCount

- 입력 문장을 단어로 분리하고 Mapper에서 단어마다 `(단어, 1)`을 출력했다.
- Shuffle 단계가 같은 단어의 값들을 묶어 `(단어, [1, 1, ...])` 형태로 Reducer에 전달한다.
- Reducer는 값들을 모두 더해 단어별 등장 횟수를 출력한다.

### 첫 글자 카운트

- `Wordcount.java`를 복사하여 `Wordcount1char.java`를 만들었다.
- 각 단어 전체 대신 `token.substring(0, 1)`을 Key로 출력하여 첫 글자별 등장 횟수를 집계했다.
- 파일 이름과 `public class` 이름이 일치해야 Java 컴파일이 가능하다는 점을 확인했다.

### 사용자 정의 Partitioner

- `Wordcountsort.java`에 `Partitioner<Text, IntWritable>`를 상속한 `MyPartitioner`를 작성했다.
- Key의 첫 글자를 `key.toString().charAt(0)`으로 확인했다.
- 첫 글자가 소문자 `a`보다 앞선 문자는 Reducer 0으로, 나머지는 Reducer 1로 보냈다.
- Reducer가 2개이므로 결과가 `part-r-00000`, `part-r-00001` 두 파일로 나뉘었다.

### 역색인(Inverted Index)

- 일반 색인이 문서에서 단어를 찾는 구조라면, 역색인은 **단어를 기준으로 그 단어가 등장한 문서와 위치를 찾는 구조**다.
- Mapper는 `(단어, 파일이름:오프셋)`을 출력했다.
- Reducer는 같은 단어에 속한 위치들을 문자열로 연결하여 출력했다.
- `FileSplit`을 사용하려면 `org.apache.hadoop.mapreduce.lib.input.FileSplit` import가 필요했다.

### Driver 등록과 빌드

- 새 프로그램은 `Driver.java`의 `ProgramDriver`에 `addClass()`로 등록해야 `hadoop jar` 명령에서 실행할 수 있다.
- `ant`로 소스를 컴파일하고 `ssafy.jar`를 다시 생성한 뒤 HDFS 입력·출력 경로를 지정하여 실행했다.
- `Unknown program` 오류가 발생하면 Driver에 등록된 실행 이름과 명령어의 이름이 일치하는지 확인해야 한다.

### 핵심 정리

> Mapper가 어떤 Key를 만들고 Partitioner가 그 Key를 어디로 보내는지에 따라 같은 MapReduce 구조로 다양한 집계와 검색 인덱스를 구현할 수 있다.

### 1. 공개 규모와 실제 확보 가능량은 다르다

세 가지 데이터에서 동일한 패턴을 확인했다.

| 데이터 | 공개된 규모 | 실제 접근 조건 |
|---|---|---|
| NCBI SRA (유전체) | 페타바이트급 | **월 5TB 복원 제한** + 리전 밖 전송료 + 샘플당 700MB~수GB(소규모 파일 다수) |
| 도서관정보나루 | 대출 23억 건 | **공개 API는 집계 순위만 제공**, 원자료 미개방 |
| Steam 마켓 데이터 | 거래 활발 | **공식 API에 가격 이력 없음**, 비공식 경로는 분당 20회 제한 |

데이터셋 규모만으로 계획을 세울 수 없으며, 신청 절차·쿼터·필드 구성을 함께 확인해야 한다.

### 2. 데이터 성격에 따른 접근성 패턴

여러 후보를 검토하면서 일관된 규칙을 확인했다.

| 데이터 성격 | 접근성 |
|---|---|
| **정부·과학·인프라 공개 데이터**<br>(Common Crawl, 위성, GH Archive, Software Heritage, OSM) | 대체로 접근 가능 — 재사용을 전제로 공개된 데이터 |
| **상업 플랫폼 보유 데이터**<br>(쇼핑몰, 항공권, 게임 마켓, OTT) | 대체로 차단 — 크롤러 차단·로그인 요구·유료·쿼터 |

검토한 후보 중 상업 플랫폼 데이터가 실제로 확보된 사례는 없었다.

### 3. Common Crawl로 국내 쇼핑몰 데이터는 확보되지 않는다

상품 가격·용량 변화 추적 아이디어를 검증하기 위해 Common Crawl 인덱스를 직접 조회했다.

| 사이트 | 인덱스 수집량 | 실제 내용 |
|---|---|---|
| **www.coupang.com** | 13건 | **전부 robots.txt**, 실제 페이지 0건 |
| coupang.com 서브도메인 | 14,282건 | 대만판(9,555), 뉴스(1,958), 개발자문서(1,720) — 국내 쇼핑 페이지 아님 |
| **search.11st.co.kr** | 7,193건 | **검색 파라미터에 주입된 SEO 스팸**, 상품 데이터 아님 |
| gmarket.co.kr | 소수 | 홈페이지 루트만 반복 수집 |

국내 주요 쇼핑몰 3곳 모두 상품·가격 페이지가 확보되지 않았다.

**원인**: 대형 쇼핑몰은 크롤러를 차단하며, 상품 목록을 JavaScript로 렌더링한다. Common Crawl은 정적 HTML만 수집하므로 구조적으로 접근이 불가능하다.

### 4. 범위를 좁힐 때 데이터 규모가 함께 줄어드는 구조는 부적합하다

논문-원시데이터 교차검증 아이디어를 검토하면서 확인한 딜레마다.

| 작업 | 필요 데이터 | 규모 |
|---|---|---|
| 접근번호 추출 | 논문 텍스트 | 수백 GB |
| 메타데이터 대조 | SRA **메타데이터** | **수 GB** — 단일 노드로 처리 가능 |
| 샘플 중복 탐지 | SRA **원시 FASTQ** | 10TB+ |

구현 난도를 낮추기 위해 범위를 좁히면 분산처리의 필요성이 함께 사라진다. 다른 후보(코드 이력 분석, 해양 데이터)는 범위를 좁혀도 스캔 대상 총량이 유지되는데, 이 후보만 함께 감소했다.

**아이디어 평가 기준으로 "범위를 좁혀도 데이터 규모가 유지되는가"를 추가했다.**

### 5. 문화·여가 도메인의 구조적 제약

7개 영역을 검토했고 각각 다른 이유로 기각됐다.

| 영역 | 기각 근거 |
|---|---|
| 항공 지연 분석 | 상업 솔루션 시장 포화 (SkyBreathe, NetLine 등) |
| 폭염·대기질 | 공공데이터 활용 주제로 중복도 높음 |
| 상품 가격 추적 | 데이터 수집 차단 (3번 참고) |
| 영화·음악·OTT | 공개 데이터가 GB 수준 (메타크리틱 리뷰 160만 건 ≈ 1.3GB) |
| 여행 | 텍스트 기반으로 규모 부족 + 관광 데이터랩이 통신 데이터로 유사 분석 제공 |
| 게임 전적·통계 | 기존 서비스 포화 |
| 게임 마켓·포럼 | API 미제공 또는 약관 제약 |

**공통 원인**: 여가 콘텐츠 데이터는 플랫폼이 보유하거나, 공개되더라도 텍스트 기반으로 규모가 작거나, 규모가 큰 공개 데이터는 이미 해당 데이터 기반 서비스가 존재한다.

### 6. Steam 리뷰 API 실측

Steam 리뷰 API를 호출해 응답 구조를 확인했다. **인증키가 필요하지 않다.**

```
https://store.steampowered.com/appreviews/{appid}?json=1&filter=recent&language=all&num_per_page=20&cursor=*
```

| 항목 | 값 |
|---|---|
| 리뷰 1건 평균 크기 | **약 871바이트** |
| 응답 필드 | 작성자 플레이타임, 언어, 구매 여부 등 |

**분석에 활용 가능한 핵심 필드를 확인했다.**

```json
"playtime_forever": 13148,
"playtime_last_two_weeks": 977,
"playtime_at_review": 13148
```

리뷰 텍스트(진술)뿐 아니라 실제 플레이 시간(행동)으로 교차 검증이 가능하다는 의미다.

### 7. API 파라미터 기본값 확인의 중요성

CS2 총 리뷰 수가 523만으로 조회됐으나, 상점 페이지 표시값은 900만 이상이었다.

**원인**: `purchase_type` 기본값이 "스팀 직접 구매자"로 한정되어 있었다.

| 파라미터 | total_reviews |
|---|---|
| 미지정 (기본값) | 5,234,579 |
| **`purchase_type=all` 명시** | **9,813,721** |

**데이터의 약 47%가 오류 없이 누락된다.** 예외가 발생하지 않으므로 값만 보고는 인지할 수 없다.

이후 모든 수집에 `purchase_type=all`을 명시하기로 했다.
